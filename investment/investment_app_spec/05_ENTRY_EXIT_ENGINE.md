# Entry / Exit Engine Specification v1.3

## 2026-09-29 正式更新：価格構造先行・RR参考化（screening-1.4.0）

本更新を以下の旧条件より優先する。現実的なEntryと最初の主要抵抗から第1利確を決め、上昇余地>=5.0%を確認後、採用支持帯の下抜けから損切を定め、最後にRRを参考値として計算する。RRは採用・除外・選別条件にしない。低RRでも構造と5%以上の条件を満たせば残す。
Entry起点と利確起点の両方で既存Bandを検証する。利確/1.05はEntry上限であり価格を生成しない。現在値から10%以内の実支持帯のみ、直上の主要抵抗を飛ばさず検証し、同じ支持帯・第1抵抗は統合。近い順に押し目最大2つ、現値を含め最大3つ。有効候補のみ画面・コピーに出す。損切・抵抗の重要度・価格をRRのために調整しない。
Entry候補なし・plan_missing・現実的targetなしはscreeningではWarning/要確認、価格戦略は見送り。真のCritical・確認済み業績悪化・下降構造・重大流動性問題の非通過は維持する。
一次定量評価はweighted_availableの評価済み範囲内の加重平均を維持し、coverageで減点・無効化・0点補完しない。coverage不足は要確認。通常表示は点数とcoverageを分け、未カバー客観項目をcatalogの人間向けlabelでChatGPTへ渡す。定性調査項目は別枠とし、アプリ点数は再計算せず、補完情報を利用者の最終判断に使う。

## 2026-09-29 追加更新：現実的なEntry範囲と有効候補のみ表示（screening-1.3.0）

既存pullback_search=0.1を探索限界として使用する。押し目は分析時の現在値から10%以内に存在する実支持帯だけを近い順に独立検証し、範囲を下回った時点で探索終了。境界価格からEntryを作らず、抵抗・損切・Band品質を調整しない。最新採用条件は第1利確上昇率>=5.0%（ちょうど5%も含む）かつRR>=1.3。最大2つの有効な押し目だけを採用する。
条件未達の現値プランは採点の内部診断として保持できるが、Entry戦略、上段価格、選択肢、ChatGPTコピーには表示しない。保存済み履歴にも同じ表示フィルターを適用し、元の保存内容は変更しない。有効候補ゼロなら価格戦略は「見送り」とし、10%以内では条件を満たす有効候補がない旨を表示する。銘柄の一次判定・定量評価・Entry品質とは分離する。本追加更新は下記の5%超、不採用シナリオ比較表示、無制限探索に優先する。

## 2026-09-29 更新：実用Entryの最低上昇余地（screening-1.2.0）

全時間軸・各シナリオで、既存の構造的支持帯→通常損切→最初の主要抵抗に基づく第1利確を固定し、(第1利確−Entry)/Entry×100 が5.0%超、その後RR>=1.3を満たす場合だけ採用候補とする。5.0%ちょうどは不採用。利益率から価格を逆算せず、strong_bandの基準を変えず、最初の主要抵抗を飛ばさず、損切を狭めない。
押し目は既存支持帯を近い順に独立計算し、条件を満たす独立支持帯を最大2つ採用。2つに満たない場合は近い不採用シナリオを理由説明専用として比較に残す。各価格プランに上昇率・採用可否・理由を保持し、UIとコピーに明示する。全候補が不採用なら「有効なEntry候補なし／押し目待ち」。値幅・RR不足だけで銘柄全体を非通過にせず、一次判定は要確認とする。Entry技術スコアは参考値として保持するが、不採用シナリオの承認は許可しない。本更新は下記の旧Entry採用条件に優先する。

## 2026-09-24 更新：Entry戦略比較（screening-1.1.0）

通常画面では現値（任意指定時は指定価格）＋第1押し目＋第2押し目の最大3シナリオを比較する。現値の既存計算は維持。押し目は既存の有力Bandから近い順に最大2つの独立した支持帯を採用し、各帯の下抜けから損切を先に定め、各Entry上の最初／次の主要抵抗から利確を再計算する。RR目的の価格調整やMA1本だけの機械採用はしない。期間付きMA・pivot・窓等の根拠を保持し、UIとChatGPTコピーへ表示する。
RR<1.3はEntry改善待ち、1.3以上1.5未満は最低限／要確認、1.5以上2未満は許容、2以上は良好。現値RR不良時は押し目の独立RRを併記する。押し目も1.3未満なら価格戦略上の妙味が乏しいと要確認にするが、RR単独で非通過にはしない。候補到達時のEntry品質・反転確認は未確定であり、一次判定・最終売買判断の役割分担は変更しない。

更新：2026-09-10。RR式、損切先行、7%未満の例外を確定方針に合わせて改訂。

## 1. 基本思想
価格目標をAIが自由生成しない。プログラムが実データから候補価格帯を生成し、AIは文脈と根拠を評価する。
第1損切＝通常損切。最終損切および価格に依存しない撤退条件とは分ける。
RR =（第1利確 − Entry）÷（Entry − 第1損切）。

## 2. 支持・抵抗候補
- 直近／過去高値・安値
- 13/25/50/75日線、13/26/52週線
- Bollinger Bands
- Fibonacci 23.6/38.2/50/61.8/78.6
- 価格別出来高、窓、心理的節目

欠損した指標をAIで補わない。日足OHLCと総出来高から作る近似分布を実測の価格別出来高と呼ばない。
Fibの起点と高安の確定条件には分析時点以降の情報を使わない。

## 3. Confluence（近接する支持・抵抗の重複帯）
価格差とATR等に応じて近接価格帯をまとめる。強度評価：
- 独立した根拠の種類（同系列指標の過大な二重計上を避ける）
- 週足根拠を日足より重視
- 過去反応回数、出来高量、直近性

許容幅・強度係数の初期値は14。将来の実績検証で校正可能なconfigとして版管理する設計とし、今回はconfigファイルを作成しない。
スイングでは週足、主要高安、実測価格別出来高を優先し、同系列の派生指標の本数で強度を水増ししない。

## 4. 算出順序
1. 分析時点、時間軸、現値／指定Entry、局面を固定。
2. 実支持帯とシナリオ無効化条件を特定し、第1損切・最終損切を先に定める。
3. 抵抗帯等から第1利確・最終利確を算出。
4. Entry候補を定め、上記の固定された根拠付き水準でRRを算出。
5. RRが悪い場合はEntry価格改善を検討し、押し目・反転・ブレイク待ちのプランを生成。
6. 根拠のない改善価格、ゼロ以下の損切距離、利確がEntry以下の場合は有効プランにしない。

RR>=2.0は良好、1.5<=RR<2.0は条件付き、RR<1.5は原則Entry改善・押し目待ち。
1.5未満は買いを支持する支配的材料がある場合のみ例外を検討できる。RR単独で見送りへ足切りしない。
損切価格をRRから逆算して移動しない。
同じシナリオのEntry比較では利確と損切を固定する。
新しい支持帯等でシナリオが本当に変わる場合は、新しいプランと根拠・変更理由を保存する。

## 5. 利確と7%未満ルール（スイング）
1. 現値+7〜20%を基本探索範囲としつつ、7%未満の手前抵抗も必ず検出する。
2. 最初の有力抵抗帯を第1利確、次の有力帯／強気シナリオを最終利確候補とする。
3. 強烈な業績・材料変化時は20%上限を外せるが、目標の根拠は必須。
4. 現値から第1利確まで7%未満は原則押し目待ち。投資妙味は原則下げずEntry品質へ反映。
5. 現実的な利確水準を維持し、現値の約10%下を探索起点として実支持帯へ補正する。
6. 押し目Entry候補の約5%下は次の支持帯探索の目安。実支持帯・無効化条件から損切を定める。
7. 支配的材料と合理的RRの両方が成立する場合のみ例外を許容し、理由・Evidence・基準価格・プランを記録。

10%/5%は固定注文価格ではない。ATR・週足構造・銘柄の変動性で補正する。
「約5%下」の基準を押し目候補とするのは設計上の明確化。RR区分と例外審査は11のP04。2.0未満でも条件や支配的材料を評価し、機械的な足切りにしない。
指定Entryについても別シナリオの上値余地とRRを計算し、現値判断を上書きしない。
中長期・デイトレに7%条件を流用しない。

## 6. Alert
第1損切に達する前の再評価開始価格。Alertは自動売却ではない。
買い方向プランでは第1損切 < Alert < Entryを検証。根拠がなければ未算出。
価格の監視・通知の自動実行はMVPの確定要件ではない。

## 7. 損切と撤退
第1損切：テクニカル・需給上のシナリオが弱まる価格。
最終損切：価格構造上のシナリオ完全否定水準。
撤退：価格とは別に投資前提が崩れた条件。
- 下方修正、受注急減、重要案件失注、希薄化、不正
- テーマ実需消失、競争優位崩壊、想定カタリスト消失

撤退条件はイベント名だけでなく当初の前提と、何が崩れたら撤退するかを保存する。
根拠のない第2の価格水準を必須表示のために捏造しない。

## 8. 今買う vs 待つ
Entry/Exit Engineは価格プランを生成し、最終売買判断はDecision Engineが行う。
- 今買う：上値余地、損切距離、RR、近いカタリスト、取り逃しリスク
- 待つ：押し目候補と根拠、反転確認価値、押し目なく上昇する機会損失

各プランに成立条件・失効条件を持たせ、決算跨ぎ未入力時は複数シナリオを比較する。
分割は実行方針として最終判断と別管理する設計（11のP07）。株数・金額・注文は扱わない。
