# 初期config・数値計算仕様 v1.0

2026-09-10。実装時に設定ファイルへ移すための文書仕様。今回configやコードは作成しない。
数値は検証開始用の初期設定であり、将来実績により校正可能。ユーザー確定した責務・承認・計算式をconfigだけで撤廃しない。

## 1. 版と変更の契約
config_version、schema_version、内容ハッシュ、変更理由、検証期間、旧版、採用者を記録。
分析ごとに使用版を固定する。過去スコア・価格・承認を新設定で書き換えない。
スコア重みは正本02/03/04に一致する初期値。係数の変更も将来の比較検証を通して新しい版で採用。
config読込時に型・範囲・重み合計・単調な補間点・参照カードIDを検証し、不正なら起動時に明示エラー。
安全・承認不変条件（Critical不成立、Severeのユーザー承認、損切先行、秘密情報除外、注文なし）は数値調整対象外。

| fib.levels | 23.6,38.2,50,61.8,78.6% | 確認済み波動に適用 |

必要本数は「その特徴量を計算できる本数」から決める。要求範囲未達だけで全体を停止しない。
例：週足52週線の4週傾きを3観測点で比較するには最低58確定週足。足りなければSW-D1を未評価。
日足75日線だけなら75本、傾き・継続まで使う場合は81本。
ATR14は前日終値を含む15本以上。BBは20本。比較区間のない相対強度は未評価。
週月高安は最低2つの確定pivotが必要。月足の長期位置は24確定月足を最低比較範囲とする。
当日累積出来高を過去日の終日出来高と比較しない。同時刻履歴がない場合は相対参加の該当カードを未評価。
日足から週足／月足へ集約するときは取引カレンダーと価格調整を揃える。未完了の週月足は方向採点に使わない。

TR = max(高値−安値, abs(高値−前終値), abs(安値−前終値))。
相対強度 = 対象の期間騰落率 − ベンチマークの同期間騰落率。ベンチマークは比較目的とともに保存。
傾きは当該MA−4本前MAの符号で方向を分け、同値は横ばい。配列のみで売買判断しない。
高値pivotは左右2本以上の高値に対して最大、安値pivotは最小。横並び極値は最も新しいものを選び、右側2本完成後だけ利用。
pivotの発生日と確認日を別に記録し、バックテストでは確認前に利用しない。
Fibは時間順で最新の確定した反対種類のpivot対を起点とし、起点・終点・波動方向を保存する。
板・歩み値が任意でも、存在しない短期足・出来高値を補わない。

## 3. 支持抵抗候補と独立系統
各候補はprice_low/high、source_timeframe、family、major_flag、evidence_ids、observed_at、confirmed_atを持つ。
familyはprice_structure / moving_average / volume_profile / volatility_band / fibonacci / round_number。
主要高安・窓はprice_structure。MA各本数は同じmoving_averageで、独立系統数を増やさない。
同じ原系列からの指標は完全な独立証拠ではないため依存元も記録し、系統数は強度補助として扱う。

| key | 初期値 |
|---|---|
| timeframe_weight.month / week / day / intraday | 4 / 3 / 1 / 1 |
| source_weight.major_pivot / pivot / gap | 3 / 2 / 2 |
| source_weight.measured_volume_profile | 3 |
| source_weight.MA / BB / Fib / round_number | 1 / 1 / 0.5 / 0.5 |
| cluster.atr_factor | 0.15 |
| cluster.min_ticks | 2 |
| strength.reaction_weight / reaction_cap | 0.5 / 4 |
| strength.recency_weight | 1 |
| strength.family_bonus / family_bonus_cap | 0.5 / 2 |
| strong_band.threshold | 7 |
| stop.buffer_atr / min_ticks | 0.1 / 1 |

支持抵抗の具体的な再現手順：
1. 当該時間軸で確認済み候補を作り、採用可能な日時だけ残す。
2. 共通の許容幅をmax(2呼値, 基準ATR×0.15)とする。基準ATRはSwing日足、Mid-long週足、Daytrade5分足。
   ATR不足なら2呼値だけで候補をまとめ、精度制約を警告。未計算のATRを0と偽装しない。
3. 価格昇順で候補を処理し、帯全体の最大−最小が許容幅以内の場合だけ追加する。同値は候補ID順。
   重なりが連鎖して離れた価格まで一帯になることを防ぐ。元の広い価格帯は幅を保存し、無理に単一点へ縮めない。
4. 各family内のtimeframe_weight×source_weightの最大だけを加算する（同系統MA等の重複抑制）。
5. 独立した過去反応を数える。完成足が帯に触れ、次の完成足で帯外へ離れた動きを1回。
   連続接触は1回、再度離れてから戻った場合のみ追加。未来足で反応を数えない。
6. 直近性は最新反応から基準足5本以内=1、6〜20本=.5、21本以上または未反応=0。
7. 強度 = 系統内最大値の合計 + .5×min(反応回数,4) + 直近性 + .5×min(系統数−1,2)。
8. 有力帯は強度>=7。Swingでは週足、主要高安、実測価格別出来高由来をprimaryとし同距離では優先する。
   primaryでなくても手前の有力抵抗を飛ばさない。優先は順位付けであり抵抗の無視ではない。
9. 同距離・同強度では直近確認日、候補IDで安定順序。価格水準の有効性は根拠も画面で示す。

実測価格別出来高は取引値と数量の記録または出所付きの実測分布を使用。
日足OHLCの範囲へ総出来高を均等配分して「実測」としない。
分布から生成する際は幅max(5呼値, 基準ATR×0.1)の価格binに実取引数量を合算し、局所極大で上位20%の数量binを候補帯とする。
原データがbin形式なら幅を保存して利用。出所不明なら未使用。未取得でも他の実支持根拠を利用できる。

## 4. 価格プラン
支持候補はEntryより下、抵抗候補は上。買い方向の通常プランを対象とする。
第1損切候補は根拠付き支持帯下端−max(1呼値, 基準ATR×0.1)。ATRなしは1呼値＋精度制約表示。
支持が想定する無効化条件と合わない場合は採用しない。第1損切はEntryと利確の比率から生成しない。
第1利確は最初の有力抵抗の手前側（下端−1呼値）。中長期の根拠付き評価レンジ代替は11 P08。
Entry・target1・stop1は有効呼値へ丸めてからRR再計算。買いEntry上方向、利確下方向、損切下方向に丸め、RRを有利に見せない。
呼値表が未設定なら正確な価格プランを確定せず、候補帯と必要情報を表示する。公式表または検証済み手動入力の版を保存。
価格の順序はstop1 < Entry < target1。stop2 < stop1、target2 >= target1、stop1 < Alert < Entry。
第2帯やAlertの根拠がなければnull。表示欄自体は残す。
支持反転トリガーは支持帯への接触後、完成足終値が帯上端を上回った時点。
ブレイクは完成足終値が抵抗帯上端を上回った時点、再確認はその後の完成足が帯上端以上を維持。
出来高確認は別カードで評価し、出来高未確認をブレイク未発生と同一視しない。
日中の未完成足の一時突破だけで確定トリガーにしない。Daytradeでは5分足を使う。
今買う／待つを比較する同一構造内では利確・損切を固定。構造変更は新planと理由を保存。
押し目の約10%／約5%は探索目安。実在支持がなければその数値の注文価格を作らない。

## 5. RRと客観補間
RRの区分は07。区分の変更・承認制約の撤廃は通常の係数校正とは別の要件変更。
計算には丸め前の得点ではなく呼値調整済みの実価格を使い、RR表示の丸めは判断後。
補間を認める初期対象：
- SE-C / DE-C / ME-E内RR：x=RR、節点(0,1),(1,4),(1.5,6),(2,8),(3,10)。
- SE-A：x=上値余地百分率、節点(0,1),(3,4),(5,6),(7,8),(10,10)。
隣接節点間を線形補間し、範囲外は端の得点へ制限。上値余地は100×(target1−Entry)/Entry。
これはプログラムが客観値から行う補間で、AIの自由採点ではない。
他カードは5段階。Daytradeの余地にSwingの百分率を流用しない。
RRの補間得点は従来の帯内得点表示からの今回の明確化。RR1.5/2.0という売買条件の境界は変えない。
Entry<=stop1、target1<=Entryなら補間の前にプラン無効。負のRRを有効な低点として扱わない。

## 6. HumanReviewの初期指標
同一時点・同一資料で人間がAIを見る前に評価。比較の優先順位は以下。
1. 最終判断：今買う／条件付き／待つ／見送り／評価不能と、Severe承認待ちの一致。
2. 銘柄順位：同じ時間軸・同じ比較群。Investment順位と現在のEntry候補順位を別検証。
3. 主要理由：Evidenceに基づく作用と主要リスク。言い回し一致は不要。
4. スコア差：絶対差の平均・最大・分布を報告するだけで、それ自体を不合格の足切りにしない。

初期の受入目安（構成可能）：
judgment_agreement_min=.8、pairwise_rank_concordance_min=.8、top3_overlap_min=2、
major_reason_agreement_min=.8、unresolved_critical_disagreements_max=0。
重大な不一致とはCritical無視、Severeの未承認買い、重大悪材料の見落とし、根拠捏造、未成立プランの採用。
これらは平均一致率で相殺しない。
順位は比較可能な最低5銘柄を同一時点で確保。人間が同順位とした組はpairwise分母から除き、全組同順位なら追加標本が必要。
top3の境界同順位は候補集合を表示して重複数を数え、恣意的な銘柄名順で順位を作らない。
主要理由一致は、人間側の最大3理由のうち2つ以上（理由が1つならその1つ）を意味・根拠で再現し、主要反証の欠落がない銘柄の割合。
自動の単語一致で合否を決めず、人間が一致・差異の理由を記録する。
10銘柄レビューのほか順位比較に必要な同時点群が不足すれば追加データを用意する。
