# 実銘柄検証の準備レビュー
## 変更範囲
既存のスコア・価格エンジンを保ち、実銘柄入力、検証グループ、人間評価、差分記録を追加。
正本17文書は変更しない。外部市場API・AI・自動売買は追加しない。

## 構成
- manual_input.py：共通CSV／日本語列／CP932、利用者確認済みの補完、Evidenceと手動カード。
- validation.py：凍結入力、分析前の人間評価、5〜10銘柄、同時点、差分6分類、順位・理由比較。
- validation_ui.py：専用画面。既存結果画面へリンクして根拠・採点を参照。
- config/validation.json：正本14の比較目安と対象数。スコア配点や支持抵抗係数とは別。
- validation_*テーブル：既存SQLiteへ追加するだけ。分析・承認・既存履歴は保持する。

## 重要な制約
- 実銘柄データ未提供のため、実銘柄の結果・一致率・有効性は未検証。
- 架空データは機能テストグループに分離し、実銘柄検証へ混入させない。
- 先に人間評価を保存しないと検証分析を開始できない。結果後の評価は独立評価へ入れない。
- 独立評価の自己申告をアプリだけで証明できない。可能なら別の評価者で実施。
- 主要理由の意味の一致・重大違反は人間が確認。文章の単語一致で自動判定しない。
- 必要標本・順位・理由確認が足りない場合は未完了と表示。自動でMVP合格にしない。
- 未解消差分から修正候補を作るが、採点基準・係数は自動変更しない。
- 支配的材料・実測出来高分布・Severe条件の詳細は補足JSON経路。一般フォームへの拡充は今後の操作確認後。

## 実データ確認後の修正提案手順
1. ケースID・入力ハッシュ・規則版・Evidenceを固定して問題を再現。
2. 6分類と重大性を記録。元データの訂正か、規則の変更かを区別。
3. 原因・影響する銘柄／カード／価格／判断・推奨修正を提示。
4. 実装不具合なら既存仕様に合わせて修正し、回帰テストを追加。
5. 要件変更・配点変更が必要なら正本を勝手に変更せずユーザーへ提案。
6. 元分析を保ち、別期間・別標本で修正の妥当性を再確認。

## 停止点
検証を開始できる状態まで準備したら、具体的な必要入力を提示して停止。
実銘柄の選定やデータ不足を架空値で埋めない。外部接続の本実装へ進めない。
