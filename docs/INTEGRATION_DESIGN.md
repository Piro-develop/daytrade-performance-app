# 投資判定の統合方針（2026-09-10）

## 実装前の確認結果

1. 既存トラッカー：index.html / app.js / styles.css の静的Webアプリ。Google認証、users/{uid}/trades に売買記録。現物・信用・税額・保有配分は独立したmjs。サマリ、売買記録、成績分析、設定の4画面。
2. 判定側：Python / Streamlit。src/investment_app 内に入力、Provider、Preflight、技術計算、投資妙味、Entry、Decision、履歴、実銘柄比較を分離。現在は3時間軸UATまで実装済み。IMPLEMENTATION_RESULT.md は初期スイング版の報告なので、UAT_IMPLEMENTATION_REVIEW.md と現行コードも確認した。
3. 再利用：判定の全Engine・データ型・採点config・Evidence・CSV正規化・無料Provider・履歴・検証を investment/ に取り込む。元プロジェクトの仮想環境・実DB・ログ・個人入力・Gitは取り込まない。正本17文書を同梱し、ハッシュで一致を確認する。
4. 競合：既存「分析」は実現成績の分析。新機能は「新規銘柄判定」。投資妙味の10点と既存成績の100点は共通化しない。重複する銘柄辞書はトラッカーのstocks.jsonを再利用。売買CSVと価格CSVは別契約として扱う。
5. 構成：統合Pythonサーバーが既存静的画面と /decision/ のStreamlitを同じURLで提供。既存ナビ内に判定画面を埋め込む。Pythonの採点処理をJSへ再実装しない。起動・停止を一つにする。
6. 保存：既存Firestoreの設定・構造・保存データは変更しない。判定は専用SQLiteと添付ファイル。run_idを一意のanalysis_idとして連携用JSONへ出す。将来の連携は分析ID・シナリオ・plan_idと取引IDの関連テーブルで実現し、売買履歴や分析スナップショットを上書きしない。
7. UI：既存トラッカーに新規銘柄判定を追加。実銘柄入力、人間比較、履歴、Severe確認も同じ画面領域で利用。判定入力に口座残高・売買データを渡さない。
8. スマホ：5項目の下部ナビ。結果は時間軸選択と2列の価格カードで上段表示し、理由・Evidence・チャートは下へ展開。現在値は分析時点の値と明記。期限切れ・未算出・重大警告を維持。
9. 公開：GitHub Pages単体ではPythonを実行できない。今回のUATサーバーはPC／同じWi-Fiで利用する。将来はHTTPS、本人認証、永続ディスクを提供するホストへ移せる。Streamlit Community Cloudを選ぶ場合も既存Firebase画面を扱う統合入口が必要。ホスト決定・Firebase許可ドメイン等はユーザー確認後に設定する。

## UATの境界

- UATサーバーは起動時のアクセスコードによる単一利用者の入口。Firebaseログインは従来の売買管理にのみ使用する。分析履歴はこのUAT利用者の専用保存先で、Googleアカウント別分離は未接続。共有公開・複数利用者向けではない。
- 既存ローカル判定DBを自動移行しない。元プロジェクトは参照用として保持するが、統合版の実装・仕様はこのリポジトリ内で完結する。
- 無料公開取得→CSV／手動→画像確認の順。画像のOCR、外部AI自動送信、有料API、Windows証券アプリ接続、注文は追加しない。
- 仕様内の「実装未開始」は旧設計時点の記録。今回の実装許可はユーザー依頼を根拠とし、設計文書を書き換えない。
- 公開サーバー・認証の確認前にはGitHub Pagesで統合完了と扱わない。ローカルUAT結果を先に確認する。
